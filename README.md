# Short-Video Foraging Feed（短影音瀏覽實驗介面）

高齡者觀看 AI 微短劇的資訊覓食研究（Information Foraging Theory）實驗介面。以網頁仿製全螢幕直式滑動 feed，記錄每一次觸碰、滑動與每支影片（patch）的離開方式，供 stimulated recall 訪談與行為分析使用。

**研究主軸（proposal v3：*No Ending in Sight*）**：一支可獨立理解的短劇，在主要情節問題還沒有結果時結束，是否會影響觀眾跨過影片邊界、進入下一支之後的行為。

- **唯一的實驗操弄**：介面摩擦（零摩擦／微摩擦），各一個 10 分鐘 block，可做因果解釋
- **結尾類型**（open／closed）：不操弄，由編碼決定，自然出現在 feed 中；結果只寫成「關聯」
- 影片播完直接接下一支（不同的劇），像短劇 App 連播；每組影片有兩種播放順序

目前是 **prototype**。影片不放在網站上，施測前在手機的設定頁匯入（見「放入影片」）；測試模式下缺的影片以色塊與計時模擬播放。

## 執行

- 本機：在專案資料夾執行 `python3 -m http.server 8000`，開 `http://localhost:8000`
- 手機施測：見下一節「施測手機設定」
- 測試模式：網址加 `?debug=1`（可與專屬網址併用，例如 `?p=P01&k=6737&debug=1`）。頂端顯示目前影片、結尾類型、狀態與畫面尺寸，可設定播放加速；沒有專屬網址時可手動輸入編號與序列（加 `&o=2` 測試第 2 種播放順序）；影片沒匯入也可以開始
- 桌機測試：方向鍵上／下 = 滑動，空白鍵 = 輕點

## 施測手機設定

手機瀏覽器的網址列與底部導航列會占去高度，而且不同手機、不同瀏覽器的行為不同：有些在捲動時會隱藏網址列，有些不會。如果直接在瀏覽器分頁裡施測，同一個介面在不同時刻的可視高度可能不一樣。因此：

1. **固定一支施測手機、一個瀏覽器**。所有受試者用同一台、同一個瀏覽器，尺寸差異就只剩下面兩點要處理
2. **從主畫面開啟**：用瀏覽器開 `https://81315003e-stack.github.io/shortvideo-foraging-feed/`，選「加入主畫面」（Android Chrome：選單 →「加到主畫面」或「安裝應用程式」；iPhone Safari：分享 →「加入主畫面」）。之後**都從主畫面圖示開啟**：Android 會以全螢幕顯示，iPhone 會以獨立 App 顯示，都沒有網址列
3. **受試者代碼**：從主畫面開啟時網址固定，帶不進 `?p=&k=`。設定頁會出現「受試者代碼」欄，輸入編號與檢查碼（例如 `P05 9738`），或貼上整個專屬網址，按「載入」。驗證方式與專屬網址相同
4. **顯示模式檢查**：設定頁上方會顯示目前的顯示模式與畫面尺寸。顯示 `browser`（黃色）代表仍在一般分頁中，正式施測前要改從主畫面開啟
5. **開始時進入全螢幕**：按「開始」時，Android 會再進入全螢幕，隱藏系統導航列；iPhone 不支援，但從主畫面開啟已經沒有網址列
6. **系統手勢**：Android 的手勢導航（從螢幕最下緣往上滑 = 回主畫面）可能和「往上滑換片」衝突。建議施測手機改用三按鈕導航；介面也會記錄從螢幕上下緣 24 px 內開始的手勢（`edge_start`），分析時可另外檢查
7. **影片要在主畫面開啟的狀態下匯入**：iPhone 的主畫面 App 和 Safari 分頁的儲存空間是分開的

介面也會在資料裡記錄畫面狀態，萬一施測中尺寸改變可以查到：

- session 開始與每個 block 開始時記錄 `viewport`（顯示模式、可視寬高、螢幕寬高、裝置像素比、瀏覽器版本）
- 施測中畫面尺寸改變記錄 `viewport_change`；全螢幕進出記錄 `fullscreen_change`
- 每支影片的資料列記錄當下可視高度 `vp_h`，可把滑動距離換算成占螢幕高度的比例
- feed 期間整頁鎖定、不能捲動，所以觀看中途網址列不會被捲出或捲回

## 流程

一次施測約 45 分鐘：

| 步驟 | 時間 | 內容 |
|---|---|---|
| 1. 設定頁（研究者） | 施測前 | 載入受試者代碼、確認顯示模式與影片 |
| 2. 說明 | 約 3 分鐘 | 介紹怎麼滑、怎麼看 |
| 3. 練習 | 約 3–5 分鐘 | 2 支 60 秒影片（P01 closed、P02 open），不計時，資料標記 `practice`，不計入分析 |
| 4. Block 1 | 10 分鐘 | 零摩擦或微摩擦（依序列），播放 A 或 B 組 |
| 5. 時間估計 | 約 1 分鐘 | 受試者估計剛剛看了多久 |
| 6. 休息 | 約 2–3 分鐘 | 可延長；受試者可隨時中止 |
| 7. Block 2 | 10 分鐘 | 另一個摩擦條件，播放另一組影片 |
| 8. 時間估計 | 約 1 分鐘 | 同步驟 5 |
| 9. 結束與匯出 | 約 1 分鐘 | 研究者匯出資料 |
| 10. 回看訪談（介面外） | 約 15 分鐘 | 看螢幕錄影，優先挑看完的 open 結尾；最後問兩段比起來哪一段滑起來比較麻煩（摩擦的操弄檢核） |

- 每個 block 時間到即結束；片庫滑完也會結束，記錄 `stimuli_exhausted`
- 招募對象是平常用手機看短劇的長者；招募表另外記錄受試者平常用的手機系統（iOS／Android），施測手機不同時可當共變項
- 主要分析（設計紀錄 D29）：
  1. **接縫**：只用 `prev_completed = true` 的影片（受試者確實看到上一支的結尾），依變項為 `early_exit`（下一支開始後 10 秒內是否出現第一次有效上滑），預測變項為上一支的結尾類型、摩擦條件、feed 位置、block 順序
  2. **摩擦決定**：只用微摩擦條件中出現確認提示的離開嘗試，做描述性分析（確認與取消的次數和比例、取消後多看多久、是否再次上滑、是否最後看完），搭配訪談說明取消原因。零摩擦沒有取消選項，所以**不比較兩條件的取消率**；兩條件之間比較的是第一次上滑時間、是否出現離開嘗試、是否看完、觀看比例
  3. 往回滑、觀看比例為描述性或探索性指標
- 說明時不告訴受試者每段多長，時間估計題為輔助指標
- 兩組影片 A、B，每組 45 支 60–180 秒；每組 open 與 closed 結尾各約一半
- 序列 1–4：block 順序（零摩擦先／微摩擦先）× 影片組對應（零摩擦用 A 組／用 B 組）；另外每位受試者分配播放順序 1 或 2。8 種組合，受試者人數為 8 的倍數時完全平衡
- 序列與播放順序由指派表決定（每 8 人一輪隨機打亂），研究者不在現場選擇
- 每個 block 開始時有 300 ms 白色閃光（`sync_flash`），用來和螢幕錄影、攝影機畫面對時
- 研究者選單：左上角 1.5 秒內點三下（匯出、結束 block、中止）

## 介面流程

**10 秒只是分析窗口**：影片連續播放，不會在第 10 秒暫停，也不會出現任何提示，受試者不需要在第 10 秒做決定。受試者隨時可以上滑；10 秒內的第一次有效上滑記為 early exit，超過 10 秒的上滑照樣記錄，只是不算 early exit。

**有效上滑**：受試者主動做出、位移超過門檻（`gesture.advancePx`）的向上滑動。自然播完、系統自動切換、未達門檻的位移都不算。兩個條件都先記錄這次離開嘗試，再依條件處理：

```
零摩擦：  播放 → 影片結束前有效上滑 → 記錄離開嘗試 → 直接播下一支
微摩擦：  播放 → 影片結束前有效上滑 → 記錄離開嘗試 → 確認提示
                                                   ├─ 確認 → 播下一支
                                                   └─ 取消 → 回到這支影片繼續播
沒有上滑：播放 → 自然播完 → 自動播下一支
```

確認提示**只由「影片結束前的有效上滑」觸發**，和 10 秒窗口無關：第 3 秒、第 20 秒或第 50 秒上滑都會出現。

取消只描述行為（cancellation of the exit attempt），不直接解讀成「改變心意」；可能是想再看一下、誤觸、不確定按鈕作用，或覺得麻煩。原因由回看訪談判斷。

## Patch outcome

| outcome | 定義 |
|---|---|
| `swipe_early` | 未播完就往上滑走（微摩擦下為確認後離開） |
| `end_auto` | 播完，直接接下一支（v1.2 起兩個條件都是這樣） |
| `end_click` / `end_swipe` / `end_timeout` | 結束畫面開啟時才會出現（v1.1 以前的設定；v1.2 不使用） |
| `swipe_back` | 往下滑回上一支（回訪 patch） |
| `block_timeout` | block 時間到，截尾，分析時排除或另計 |

outcome 只描述行為；受試者當時在想什麼，由回看訪談判斷。結尾類型的關聯看**下一支**的資料列：`prev_completed = true` 時，比較 `prev_end_type = open` 與 `closed` 的 `early_exit`。自然播完（`end_auto`）不算主動離開。

## 資料

匯出三個檔案（檔名 `P{編號}_seq{序列}_{時間戳}`）：

- `.json`：完整資料（meta、設定快照、blocks、patches、events）
- `_patches.csv`：每支影片一列，主要分析單位
- `_events.csv`：每個事件一列，時間序列分析與回看片段挑選用

### patches.csv 主要欄位

| 欄位 | 說明 |
|---|---|
| `trial` / `feed_pos` / `visit_n` | 第幾個 patch／在 feed 中的位置／第幾次造訪（`visit_n` > 1 即回訪） |
| `friction` / `set` | 該 block 的摩擦條件與影片組 |
| `end_type` | 該支影片的結尾類型 `open`／`closed`（見 `docs/CODEBOOK.md`） |
| `dwell_ms` | 停留時間（含暫停與結束畫面） |
| `watched_ms` / `prop_watched` / `completed` | 實際播放長度、觀看比例、是否播完 |
| `first_touch_ms` | 進入 patch 到第一次觸碰（沒碰就是空值） |
| `n_aborted_swipes` | 有位移但未達換片門檻的滑動（猶豫） |
| `n_taps` / `n_pauses` | 輕點、暫停次數 |
| `friction_shown` / `friction_cancelled` | 摩擦提示出現與取消次數 |
| `friction_ms` / `dwell_net_ms` | 摩擦提示顯示的總時間／扣掉提示時間的停留時間（比較兩個摩擦條件時用這個，不用 `dwell_ms`） |
| `prev_video_id` / `prev_end_type` / `prev_completed` / `prev_outcome` | 接縫欄位：上一支是哪支、結尾類型、是否看完、怎麼離開 |
| `first_exit_ms` / `n_exit_attempts` | 第一次有效上滑（主動離開嘗試）距影片開始的時間；上滑次數。不論之後確認或取消都算 |
| `early_exit` | `first_exit_ms` ≤ `analysis.earlyExitSec`（預設 10 秒）；接縫分析的主要依變項 |
| `post_cancel_ms` | 微摩擦下最後一次取消到最終離開（或播完）的時間 |
| `repeat_after_cancel` / `completed_after_cancel` | 取消後是否再次上滑／取消後是否最後看完（只在有取消時才有值） |
| `order` | 播放順序（1 或 2） |
| `leave_swipe_px` / `leave_swipe_ms` / `leave_swipe_v` | 離開那一下滑動的距離、時間、速度（px/ms） |
| `vp_h` | 進入 patch 時的可視高度（CSS px） |
| `is_placeholder` | 是否為色塊模擬（測試模式缺片時） |

### events 共同欄位

`t`（ms，自 session 開始）、`wall`（epoch ms，對時用）、`type`、`block`、`friction`、`trial`、`video_id`、`pos_ms`（影片內位置）

## 設定

所有參數在 `js/config.js`：block 時間、結束畫面（依條件開關與秒數）、摩擦類型（`none` / `confirm` / `delay`）、是否允許回看、觸控門檻、顯示模式警告、刺激清單。改設定後請更新 `version`，它會寫進每份資料。

### 放入影片

影片只存在施測手機，不放進 repo，也不放在 GitHub Pages。

1. 影片依 `docs/STIMULI_CRITERIA.md` 轉檔，檔名等於 config 的影片編號：`P01.mp4`、`P02.mp4`、`A01.mp4` … `B45.mp4`。全部約 1.6–2 GB，施測手機要預留至少 4 GB
2. 把影片複製到施測手機（iPhone：「檔案」App；Android：檔案管理員）
3. **從主畫面開啟**本介面（見「施測手機設定」）
4. 在設定頁「影片」按「匯入影片」，一次選取全部檔案。介面會顯示每組匯入幾支、缺哪些
5. 正式施測時（`requireMedia: true`），受試者需要的影片沒有全部匯入就不能開始

匯入的影片存在瀏覽器的 IndexedDB，換手機、換瀏覽器或清除網站資料後要重新匯入。介面使用影片的實際長度，config 的 `durationSec` 只在缺片時使用。

## 資料安全

- 資料只存在施測裝置的瀏覽器（localStorage），不會上傳
- **受試者資料不要 commit 進這個 repo**；`data/` 與匯出檔已列入 `.gitignore`
- 真實影片可能涉及著作權，**不要上傳到 repo**；只存在施測手機與有權限控管的研究雲端
