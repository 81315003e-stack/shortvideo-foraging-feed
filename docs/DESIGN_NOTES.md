# 設計決策紀錄

每一筆記錄：決策、理由、影響、狀態。pilot 後的修改請往下加，不要改寫舊的紀錄。

## 2026-09-24　Prototype v0.1.0

### D1. 用自建網頁 feed，不用真實 App
- 理由：真實平台拿不到觸控層級的 log；固定序列才能控制刺激
- 影響：外部效度下降（沒有推薦演算法、沒有按讚留言等介面元素），需要在 Limitations 說明

### D2. 影片結束後顯示「下一支」按鍵與 10 秒倒數
- 理由：區分三種結果：未看完就走（主動離開）、看完後主動點下一支（主動繼續）、倒數結束被自動播走（沒有在做決定）
- 疑慮：結束畫面本身是一個停頓，零摩擦條件因此不是真正的無縫接續；倒數期間沒動作，也可能是在等待，而不一定是沒有決定
- 處理：做成可依條件設定（`endScreen.zero` / `endScreen.micro`），兩個條件目前都開啟、10 秒；pilot 後決定
- 狀態：待 pilot

### D3. 摩擦只作用在「提早離開」
- 理由：兩個條件在影片結束時的處理相同，摩擦只提高換 patch 的成本（對應 Marginal Value Theorem 的移動成本）
- 預設為 `confirm`（多點一下），備選為 `delay`（5 秒倒數可取消）
- 狀態：待 pilot

### D4. 允許往回滑（re-visit）
- 理由：對應 re-visiting patch；紀錄 `visit_n`，分析時可選擇排除
- 狀態：採用

### D5. 輕點暫停
- 理由：模仿真實平台；暫停次數作為沉浸或中斷的指標
- 影響：`dwell_ms` 包含暫停時間，`watched_ms` 不包含

### D6. 不放按讚、留言、分享圖示
- 理由：減少額外的可操作元素與干擾變項
- 狀態：採用，可再討論

### D7. 時間估計在每個 block 結束後立即詢問，在回看訪談之前
- 理由：回看會透露實際時間線；單題時間估計，不使用量表
- 起始值留空，避免定錨

### D8. block 用時間預算，不用固定支數
- 理由：符合 foraging 在時間限制下的取捨；片庫需多於 block 時間可看完的量

### D9. 觸控門檻（advance 80px、abort 20px、tap 12px / 350ms）
- 理由：暫定值
- 狀態：高齡者手勢差異大，pilot 時用 events.csv 的 `dy` 分布校正
