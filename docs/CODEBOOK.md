# 刺激影片編碼簿

版本：v1.2（2026-10-08）｜對應 proposal v3：*No Ending in Sight*｜選片標準見 [`STIMULI_CRITERIA.md`](STIMULI_CRITERIA.md)｜編碼表範本：[`coding_sheet_template.csv`](coding_sheet_template.csv)

> v1.0 依研究方向調整（設計紀錄 D18、D20）大幅縮減：只保留基本資訊、**結尾類型**、少數製作特徵與排除檢查。原本的開場 scent、scent–yield mismatch、視覺顯著性與內容價值編碼，完整保存在 [`archive/CODEBOOK_v0.5_scent.md`](archive/CODEBOOK_v0.5_scent.md)，留給後續研究使用。

## 0. 總則

- **分析單位**：一支影片（剪輯後的版本）
- **編碼者**：兩位，獨立編碼，編碼期間不討論
- **時間標記**：以秒為單位，取到小數點後一位（例如 `3.5`），從影片第一格畫面起算
- **觀看方式**：用電腦播放器，**完整看完整支影片**後再編碼，可以暫停、倒轉
- **不確定時**：選最保守的選項，並在 `note` 欄寫下理由，不要自己創造新類別
- **欄位名稱**：括號中的英文是編碼表的欄位名稱

### 用語對照

| 編碼簿／介面代碼 | 論文用語 | 說明 |
|---|---|---|
| `end_type = open` | open ending | 故事還沒走到結局就停住，接下來的發展留給觀眾 |
| `end_type = closed` | closed ending | 場景或故事在影片內走到一個結局 |
| `setup_given` | setup | 前因有沒有在影片內交代；沒有交代的影片不進正式片庫 |
| 摩擦條件 `zero` | zero friction | 單一滑動即換片 |
| 摩擦條件 `micro` | micro-friction | 提早離開時多一次確認點擊；不使用 microboundary，因為不預設使用者會停下來反思 |
| 一支影片 | patch | 依 Pirolli & Card (1999)；滑走 = 離開 patch，往回滑 = 回訪 patch |

**不使用 cliffhanger、unresolved**：前者容易被理解成懸疑劇，後者預設故事「應該」被解決（設計紀錄 D18）。

### 編碼部分一覽

| 部分 | 內容 | 目的 |
|---|---|---|
| A | 基本資訊 | 來源紀錄、納入排除、組間配對 |
| B | 前因與結尾類型 | 前因為納入條件；結尾類型為**主要分析變項**（RQ1、RQ2） |
| C | 製作特徵 | 描述與組間配對 |
| D | 排除檢查 | 倫理與干擾 |

## A. 基本資訊

| 代碼 | 欄位 | 說明 | 選項或格式 |
|---|---|---|---|
| A1 | `video_id` | 片庫編號 | `A01`、`B12`、`P01`（練習）；分組前先用暫時編號 `C001` |
| A2 | `source_platform` | 來源平台 | 抖音／TikTok／YouTube Shorts／Facebook／其他 |
| A3 | `source_url` | 原始網址 | 完整網址 |
| A4 | `download_date` | 下載日期 | YYYY-MM-DD |
| A5 | `orig_len_s`／`edit_len_s`／`edit_note` | 原始長度、剪輯後長度、刪除段落 | 秒；刪除段落以「起–迄秒」記錄 |
| A6 | `series_title`／`episode_n` | 劇名、集數 | 文字；整數，不知道填空 |
| A7 | `clip_start_s`／`clip_end_s` | 片段在原集中的起訖秒數（從長集數剪片段時填） | 秒；原片不剪則留空 |
| A8 | `ai_generated` | 是否為 AI 生成 | 0 = 否（真人拍攝）；1 = 部分（真人畫面＋AI 配音或 AI 臉）；2 = 全部 AI 生成；9 = 無法判斷 |
| A9 | `ai_cue` | A8 的判斷依據（可多選） | 臉部變形／表情不自然／口型不同步／AI 配音語調／畫面標示 AI／其他（寫明） |
| A9b | `ai_evidence` | AI 生成的外部證據（選片時由研究者記錄，不需兩位編碼者） | `platform_label` = 平台標示 AI 生成（例如 TikTok 的 AI 標籤）；`creator_tag` = 創作者在標題、描述或 hashtag 自己標示 AI（例如 #AI短劇）；`none` = 沒有外部證據 |
| A10 | `language` | 主要語言 | 國語／台語／客語／其他 |
| A11 | `genre` | 劇情類型（可多選） | 家庭倫理／婆媳／祖孫／霸總愛情／復仇打臉／身分反轉／民間故事／生活喜劇／其他（寫明） |

**A8 判斷原則**：至少要有一項 A9 的具體線索才能編 1 或 2；只憑「感覺像 AI」編 9。

**AI 認定標準**：正式片庫只收 `ai_evidence` 為 `platform_label` 或 `creator_tag` 的影片，也就是平台或創作者有標示 AI。只靠畫面線索判斷（`none`）的影片不進正式片庫。A8、A9 仍要編，用來描述 AI 生成的程度（部分或全部），並檢查標示與畫面是否一致。

## B. 前因與結尾類型

一支完整的故事包含兩件事：**前因有沒有交代**、**結局有沒有給**。兩者分開編碼，因為缺的東西不同，觀眾的反應也不同：前因沒交代，觀眾會看不懂（困惑）；結局沒給，觀眾看懂了但不知道後來怎樣（懸念）。本研究要比較的是後者，所以正式片庫只收前因有交代的影片，open／closed 的差別只剩結局。

### B0 前因（`setup_given`）

**先編 B0，再編 B1。**

| 代碼 | 定義 |
|---|---|
| `1` | 影片內交代了衝突或情境的起因：觀眾不需要看前集，就知道角色是誰、彼此什麼關係、為什麼會有這個衝突 |
| `0` | 影片從衝突中間開始，起因要看前集或劇情簡介才知道；只有「前情提要」字卡而沒有畫面交代，也編 `0` |

- 判斷時只看這支影片本身，不參考劇名、描述或 hashtag
- `setup_given = 0` 的影片**不進正式片庫**（選片標準第 2 節納入條件 2），可作練習或備用
- 剪輯片段若從第 1 集第 0 秒開始，通常為 `1`，但仍要確認

### B1 結尾類型（`end_type`）

**每支影片都要編**，原片與剪輯片段相同。

| 代碼 | 定義 |
|---|---|
| `open` | 影片停住時，**影片本身提出的最後一個問題沒有在影片內出現結果**。例如衝突剛升高、秘密正要揭開、角色的決定還沒說出口，畫面就結束；或以「待續」、反應特寫、懸而未決的一句台詞結束 |
| `closed` | 影片內提出的問題**在影片內出現了結果**，場景或故事走到一個結局。例如衝突有了結果、秘密已經揭露、笑點已經落下；即使這部劇還有下一集，只要這支影片自己的問題有結果，就算 `closed` |

**判斷程序**

1. 看完整支影片
2. 回到最後 10 秒，找出影片中**最後被提出的問題**（衝突、秘密、懸念、待做的決定）
3. 問：這個問題的結果有沒有在影片內出現？有 → `closed`；沒有 → `open`
4. 在 B2 用一句話寫下判斷依據

**判斷原則**

- **只看這支影片自己提出的問題**，不看整部劇的大局。例如整部劇的復仇還沒完成，但這一段的爭吵已經有了結果，編 `closed`
- **不看編碼者是否滿意**：結果合不合理、精不精彩，都不影響判斷
- **結果出現後又拋出新問題**：例如爭吵結束後，最後一句是「但他不知道，真正的麻煩才剛開始」，以**最後被提出的那個問題**為準，編 `open`
- **結尾的道德總結字卡**（例如「善有善報」）出現在問題有結果之後，不改變判斷，仍是 `closed`
- **生活喜劇**：笑點落下即為 `closed`；笑點還沒出現就結束，編 `open`
- **剪輯片段**：終點依選片標準第 6.2 節剪在場景結束處；剪完後依剪輯後的版本編碼

### B2 判斷依據（`end_note`）

一句話描述最後被提出的問題，以及它的結果是否出現。

> 範例（open）：「婆婆拿出存摺正要說是誰的，畫面結束」
> 範例（closed）：「兒子當眾拆穿媳婦的謊言，媳婦道歉」

用於描述片庫與 A、B 兩組的配對，不是主要分析變項。

| 代碼 | 欄位 | 說明 | 選項 |
|---|---|---|---|
| C1 | `subtitle` | 是否有對白字幕 | 0／1 |

## D. 排除檢查

任一項編 1，影片就排除（對應選片標準第 3 節）。

| 代碼 | 欄位 | 內容 |
|---|---|---|
| D1 | `ex_political` | 政治、宗教宣傳、選舉 |
| D2 | `ex_violence` | 血腥暴力、性暗示、自傷自殺 |
| D3 | `ex_advice` | 醫療、投資、保健食品等具體建議 |
| D4 | `ex_ad` | 導購、業配、QR code |
| D5 | `ex_viral` | 近期爆紅、受試者可能看過 |
| D6 | `ex_celebrity` | 可辨識的公眾人物 |
| D7 | `ex_series` | 同一部劇在正式片庫中已有 1 段 |

## 信度程序

1. **訓練**：兩位編碼者一起編 10 支**不在片庫中**的影片，逐項討論，必要時修訂本編碼簿（版本號加 0.1，寫進修訂紀錄）
2. **獨立編碼**：每人獨立編完全部候選影片
3. **信度計算**：`setup_given`、`end_type` 與 `ai_generated` 計算 Krippendorff's α（名目尺度）
   - α ≥ .80：可直接採用
   - .667 ≤ α < .80：可採用，但在論文中說明
   - α < .667：回到訓練步驟，修訂 B1 的定義或判斷原則後重編
4. **解決不一致**：兩人對照各自的 `end_note` 討論，達成共識，並保留原始編碼
5. **最終值**：共識後的數值寫入 `final_end_type`

## 編碼結果如何進入實驗介面

| 編碼欄位 | `js/config.js` 欄位 | 說明 |
|---|---|---|
| `video_id` | `id` | 也是影片檔名，例如 `A01.mp4` |
| `final_end_type` | `endType` | `open`／`closed`；介面把它寫進每支影片的資料列（`end_type`） |
| `edit_len_s` | `durationSec` | 匯入影片後，介面會改用實際長度 |

分析時，每支影片的資料列已經帶有 `end_type`；下一支影片的資料列帶有 `prev_end_type` 與 `prev_completed`，可以直接比較看完 open 與 closed 結尾之後的行為（下一支開始後往回滑、下一支多快被滑走）。
